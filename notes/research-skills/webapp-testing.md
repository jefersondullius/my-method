## Addendum (live, 2026-08-13) — manual-copy question and a live bug finding

**Q1 reconfirmed, with a new finding:** still absent from the official marketplace as a standalone plugin. The `anthropic-agent-skills` marketplace (hosted inside `anthropics/skills`) declares 3 nominal plugins — `document-skills` (4 skills), `example-skills` (12 skills, includes `webapp-testing`), `claude-api` (1 skill) [https://github.com/anthropics/skills/blob/main/.claude-plugin/marketplace.json — accessed 2026-08-13]. **An open GitHub issue, `anthropics/claude-code#53426`, documents that this per-plugin skill filter is currently broken**: when several plugins in one marketplace share `source: "./"` with no individual `plugin.json`, the `plugins[].skills` filter is ignored, and installing any of the 3 actually pulls in all **17** skills of the repo, not the declared subset. The issue was closed as a duplicate, with no public confirmation of a fix [https://github.com/anthropics/claude-code/issues/53426 — accessed 2026-08-13]. **Practical consequence: there is currently no way to install just `webapp-testing` via `/plugin` at all** — you either skip it or take all 17.

**Q2 — manual copy:** Apache 2.0 reconfirmed. The bundled `scripts/with_server.py` is a convenience helper for server lifecycle (start/stop), not a hard dependency — the skill's core method (write native Playwright scripts) survives copying only `SKILL.md`. Runtime dependencies (Python, `playwright` pip package, Chromium) must be installed separately either way — this is identical cost regardless of channel, so it does not tip the trade-off toward either option.

**Q3 — trade-off:** Today, `/plugin` brings 16 unrelated skills as a side effect of the bug above; manual copy avoids that entirely and lets you cherry-pick just this one, at the cost of no auto-updates from the marketplace.

**Decision 2026-08-13:** not installed via any path. Even setting aside the bug, no project trigger has fired to justify the cost.
