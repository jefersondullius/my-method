## DEFECTS — something the matrix or research/13 depends on changed or broke

### D-B1 — `gitleaks git -s .` is not a valid gitleaks invocation

**Severity: this is the one real breakage found this run.** Any project that
follows row 8.1 literally runs a command that exits with an unknown-shorthand
error and scans nothing — a secret-scanning check that *appears* to be wired up
and is not. Row 8.1 is the check that enforces the global CLAUDE.md rule "no
key, password, or token ever goes into a versioned file", so a silent failure
here is expensive.

**What is wrong:** `-s` / `--source` is registered **only** on gitleaks'
deprecated `detect` and `protect` commands (`cmd/detect.go:38`,
`cmd/protect.go:18`). The `git` subcommand takes the path as a **positional
argument** (`Use: "git [flags] [repo]"`, `Args: cobra.MaximumNArgs(1)`), and no
`-s` shorthand exists among the global persistent flags. Verified against both
